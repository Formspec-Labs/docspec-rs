Run only after independent review and all local checks, with Cargo/provider jobs idle. This is opt-in destructive qualification of a NEW `docspec-rs-qualification-<canonical UUID>` dataset, NEW physical namespace generation and NEW `maintenance` R2 prefix. Refuse an existing physical generation before effects. Retain every reference, point, journal, log and surviving object; delete no prior qualification data.

Use the existing explicit R2/Basin environment plus `DOCSPEC_QUALIFICATION_PYTHON` (absolute interpreter with boto3 installed) and `DOCSPEC_REMOVAL_ISSUER` (absolute checked-in issuer path). Execute only `engine::remote_build_provider_tests::maintenance::exact_remote_removal_and_detached_restore_reconcile_from_fresh_hosts`, ignored, remote+test-util, single test thread. Root must impose a whole-run deadline above the fixture's 720-second limit and retain partial output on failure. Do not rerun a fresh UUID automatically after an unknown result. The retained host directory is printed before setup; atomic synced nonsecret `setup.json`, `removal.json` and `restore.json` handoffs save exact pins/unused request, saved removal intent/point, and source/target generations before the respective effects. On failure use existing public resume/restore APIs from those references; do not repeat Build. This test is not an automatic arbitrary-phase restart driver. A failed stale-actor demonstration needs a separate bounded replay and is not silently counted as passing.

## Preregistered sequence and literal checks

1. Build four source rows once: two identical `(1,"same")`, `(2,null)`, `(2,"")`, plus private synthetic canary. Select an export of `counter,text`; no private canary appears in the export schema. Create a second export through durable transfer but stop before channel selection. Remove only external producer file; retained admitted bytes stay available.
2. Close data Engine. On the original host generation under explicitly quiescent maintenance, retire only the unselected export recovery. The current selected export and its recovery remain live. Capture a portable catalog-loss point. Its decoded exact closure contains current source payload and current export, excludes unused export.
3. Preview current source/current export/unused export. Both current files must have legitimate protection; only the exact unused file may enter immutable removal intent. Hold a real configured export reader; same-host prepare must wait until its admitted stream is dropped. Scope temporary credentials from the SAVED intent.objects only.
4. Mint 120-second R2 HeadObject/DeleteObject-only JWT for that one exact key using the official local signing template. Engine deletion verifies original identity and performs real DELETE; stop at removal-unlink before journal acknowledgment. Close host, resume same saved intent on fresh host. Require complete, absent-reconciled byte count equal exact obsolete length and acknowledged-unlink bytes zero. No new object URI, no blind DELETE retry. Counts do not establish packet/request counts without transport instrumentation.
5. A separate 20-second same-key temporary session must HEAD missing allowed key404, reject HEAD current key403, reject GET allowed key403 and reject PUT an unrelated fresh empty canary key403; a subsequent allowed HEAD404 proves session was still live through these scope checks. After expiry+2, allowed HEAD must403. The probe process has temporary credentials only. Keep failures, including any unexpected empty canary write; no cleanup sweep. The main Engine process retains broader read/catalog credentials; supported DELETE methods exclusively use temporary operator, not hostile-process isolation.
6. Wait until every issued destructive session expires before catalog restore. Expiry alone does not stop previously accepted effects: the deleted key remains permanently unavailable/non-reused and absent from live restore closure. The maintained DELETE reconciled absent before this wait.
7. Capture one original physical lifecycle native fence commit from a separate test-binary OS process in a test-only forwarding adapter before native effect. Keep this controlled stale actor held; all other actors are stopped. Restore the live point into one fresh target generation, stop after old registrations detach, close source host. Fresh maintenance host reuses the same exact point, target generation and false import-mode intent, then finishes registration and advances the captured lifecycle epochs. Forward original held TableCommit unchanged; provider must refuse. The wrapper neither rewrites requirements nor fabricates refusal.
8. Fresh target host must return the same exact selected source and export pins. Independently stream each once against literal duplicate/null/empty oracle; export checks exact native field IDs/types/nullability and excludes private field. Read restored authority epoch, advance it by one and retain same selected source: new generation stays writable. Point remains live throughout deletion/restore.

## Limits and interpretation

Engine budget: 256MiB memory, 16MiB scratch, one compute thread, eight-row batches, 1MiB decoded batch, 4MiB metadata. Four rows and one obsolete flat file; at most eight scoped keys in issuer, request/output16KiB, native hold180s, issuer55s, whole fixture720s. These bounds are watchdogs, not throughput or latency targets. Measure outer wall/RSS/peak logical+allocated host disk if running; include credential wait, failed-before-ack deletion and full cold reconciliation/restore/readback cost. Retained metadata/native candidates are expected; no catalog/object garbage sweep.

This qualifies a declared quiescent source-only catalog-loss profile using same immutable object URIs, not online restore, object-loss backup, remote groups, global reader discovery, distributed lease, credential revocation, hostile process isolation or power-loss durability. The controlled held old actor demonstrates physical identifier fencing; external operators remain responsible for stopping other hosts and permanently preventing key reuse. No row receipt is claimed for source-only data. Repeated point restoration to later generations is outside this single provider run.

Official JWT template: https://developers.cloudflare.com/r2/examples/authenticate-r2-temp-credentials/ ; permission model: https://developers.cloudflare.com/r2/api/s3/temporary-credentials/ . Issuer performs local signing only, does not create/rotate parent credentials or request a catalog token.
