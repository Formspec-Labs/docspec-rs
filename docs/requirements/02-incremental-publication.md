# R2 — Publish consistent releases for actual consumers

Status: greenfield implementation plan. [Shared decisions](../PLAN.md) govern publication, coverage, and retention. There is no requirement to preserve a current exporter or Python-only format.

## User outcome and requirements

“A small update becomes available promptly, and every reader can reproduce the exact data, schema, and evidence it received.”

A release is immutable and independently readable. Its channel pointer selects one complete release. Interrupted publication preserves the previous release and can resume without uploading verified unchanged objects again.

## Design

Identify actual consumers before freezing the format: application, browser, SQL, analysis tools, and bulk downloads. Record supported types, delete handling, evidence access, acceptable freshness, and authentication. Native releases remain the canonical published dataset. Provide thin read adapters or derived flat shards when consumers require them; a monolithic download is an explicit distribution with its own cost.

A release root binds dataset/version references, stable field IDs and schema interpretation, completed results and exact input coverage, processing definitions, required evidence, disclosure policy, and immutable physical references. It may refer to shared or partitioned manifests to avoid repeatedly copying complete inventories; measure traversal and verification costs. Use a maintained manifest/admission format where suitable instead of inventing equivalent hashing and membership machinery.

Readers resolve a channel once and remain on the selected pin. They apply effective membership and deletes, enforce bounded I/O, and verify required metadata and object identity. A plain Parquet glob is not equivalent to a snapshot containing deleted rows. Reuse of prior verification requires the same qualified immutable identity and trust boundary; cache presence alone is not verification.

Use R1's shared selected-input/read context and maintained decoders/member resolution throughout preparation and admission. Equivalent checks in the same qualified scope may reuse retained validation results; independent public readback remains a separate trust boundary. Do not rebuild evidence semantics in release-specific scripts. Evidence-only changes produce new completed result/release evidence without unnecessarily rewriting unchanged subject values, while checks depending on the changed evidence rerun.

Logical selection does not authorize physical disclosure. Every byte of a reused public object must be permitted, including superseded or unselected rows and metadata. Otherwise refuse or explicitly materialize authorized scope. Compare file grouping by disclosure policy and update behavior against fragmentation and read cost. A policy change revalidates reuse. Historical bytes already disclosed by an earlier release cannot be made undisclosed by a later delete.

Flat or combined-table materialization is a derived result pinned to the canonical release. With qualified shard boundaries, regenerate changed shards and reuse unchanged authorized objects. Prove exact population and type equality; do not assume materialization is incremental or free. Base comments and enrichments must have compatible source/coverage bindings, including any explicit correspondence evidence permitting value reuse.

Routine releases may cover consistent captured inputs while sources continue advancing. Check application-defined input relationships and nonregression against the prior release using the shared coverage rules. An expected-pointer check alone does not prevent an older candidate from being retried against a newly read pointer. Strict latest-input eligibility is explicit policy; publication time is not processing freshness.

Commit candidate protection and publication intent durably before external pointer compare-and-swap. Record expected pointer, release identity, active authority/definition, and coverage. Bind each attempt to its publisher authority epoch and qualify handoff at the external pointer boundary: a stale attempt cannot acquire a replacement epoch or publish merely because it held permission earlier. Use conditional pointer tokens and actual storage-access fencing where required; a catalog lease check alone does not make a later external write atomic. Verify readback and durably reconcile afterward. A crash leaves protected, inspectable intent. Anonymous readers rely on declared release availability windows; explicit reader pins or leases are separate capabilities.

Preserve durable phase handoffs between source/receipt restoration or transfer, generation validation, remote upload, public promotion, and readback. R1 phase results record exact selected pins, output identity, completion checks, and remaining work. Transfer success does not establish full validation. After interruption, resume the first incomplete or invalidated phase using retained bytes; do not recopy a qualified subject or receipt stream merely because the parent operation did not finish. After a confirmed public write, resume readback without another public write. Structured validation/readback results survive optional report-rendering failure. Protection remains until explicit R6 retirement.

## Measurements and decisions

Compare first release, unchanged repeat, small append, correction, removal, schema evolution, enrichment update, evidence-only change, and interruption/resume at each costly boundary. Hold changed rows fixed while increasing data and history. Record selection, decoding and validation passes; bytes restored/transferred/reused; objects scanned/hashed/materialized/uploaded; requests; manifest growth; phase-commit cost; candidate-to-visible time; fresh-reader cost; whole-process/engine memory; and scratch high-water use. Compare disclosure layouts and required flat distributions on equivalent consumer output. Measure independent checks separately from avoidable repetition, including cold admission and required recovery.

Choose consumer formats, disclosure rules, availability windows, and input-version relationships before relevant format/qualification gates. Missing consumer requirements block format freeze, not fixture work. Additional formats need a concrete consumer and measured cost; they do not create an independent data authority.
