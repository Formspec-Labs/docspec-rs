## Patch summary and function trace

The patch adds nullable Boolean/Long/Double/String roots and future omission-default edits to `SchemaSpec`. Each addition gets a stored required Boolean supplied marker in the same pinned Iceberg schema. Initial defaults interpret old physical absence; incoming omissions use the current write default. Internal rewrites carry stored value/marker pairs unchanged. The operation upgrades affected tables to Iceberg v3 without rewriting existing payloads.

## Data flow and invariants

- Logical field IDs and generated marker IDs come from one native allocator. Marker names derive from logical IDs; public edits cannot relabel marker identities. Retained history keeps future allocation above retired IDs even when no marker remains current.
- Old physical absence reads as `(initial default or null, false)`. Fresh omission becomes `(current write default or null, false)` exactly once. A supplied null or equal-default value has a true marker. Internal kept/removed-row rewrites preserve the existing pair, so changing a future default cannot reinterpret rewritten old rows.
- Request identity records declared defaults; rebuild material identity includes required schema/history/allocation state; physical source identity remains provenance. Computation over unchanged rows does not depend on a future omission rule.
- Metadata-only edits retain exact old objects. Native schema interpretation is qualified independently from physical footer identity, so skipping a repeated footer check does not skip new read-rule validation.
- Source preparation still happens after guarded operation capture and before validation/group composition/selection. The final wrapper adds no task, runtime, payload read or new lifecycle phase, and does not loosen cancellation or authority checks.

## Limits and conclusion

No material finding remains open for the inspected candidate. Coverage of the changed paths is adequate for this slice; confidence is high.

The explicit key-marker probe can scan every replacement marker when all keys are supplied. It is a narrow correctness check before scope derivation, with bounded output, not a constant-I/O operation. Default expansion admission estimates predictable per-batch allocation; it is not a whole-process memory guarantee. Metadata/history hashing and qualification remain proportional to bounded native history.

Supported additions are nullable roots of the declared scalar types. Nested/type evolution, related-output edits, global IDs across non-evolved rebuilds, wider continuous-ingestion/cutover qualification, and full R3/performance acceptance remain outside this result. Combined output alone does not expose omission state; raw source groups and explicitly authored scalar expressions provide it. No Comments-scale measurement of schema latency, marker storage overhead, long-history growth or maintenance reclamation was performed in this slice.
