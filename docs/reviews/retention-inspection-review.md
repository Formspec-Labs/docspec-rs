## Data flow and invariants

- New backfill dependencies originate from the actual `source` and first retained prepared table. They persist in lifecycle rows and do not relabel prior completions. Legacy absence remains unknown to inspection, while ordinary recovery can still read the original serialized shapes.
- Candidate identity, visited metadata and a first blocker live only inside this request. Returned objects and boundaries escape as a report; no persistent index or alternate lifecycle authority is added.
- Complete native pins are trusted because supported writers already admitted their exact inventories. Inspection does not requalify arbitrary forged or corrupted pins. Compact references without such a pin require metadata expansion. Conflicting candidate references or metadata interpretations refuse.
- Each lifecycle view is immutable, but the report does not claim a single catalog-wide atomic snapshot. Concurrent work can add roots during or after inspection. `RetentionInspection` states this explicitly (`src/model.rs:514`). Unmatched means no witness in the observed views, not safe to delete.
- All issued result/readback closures and unretired reservations remain roots. No phase-retirement policy, availability barrier, deletion operation or restore promise is introduced.
- Candidate/traversal state and external metadata admission are bounded. Catalog enumeration allocates inside the maintained adapter before the application's bound check. Native manifest I/O can still repeat across distinct metadata generations; `metadata_objects_read` is not a complete request/byte counter or proof of a whole-process memory ceiling. Scaling remains unmeasured.
