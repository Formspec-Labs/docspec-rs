## Data flow and invariants

- **Stable retry identity:** the receipt is checked before current-generation validation. An identical completed retirement returns its original receipt after later commits; a changed plan under the same identity refuses. No successful retry appends another decision.
- **Exact generations:** retirement leaves the original completion row/material key intact. The marker includes native revision, so a subsequently committed generation gets no automatic retirement. Fresh execution compares every submitted generation with its current row before writing any decision.
- **One local authority boundary:** ordinary services hold readers; retirement owns the writer and only then takes dataset locks. No public shared helper is called beneath the writer in the inspected executor. The common guarded lifecycle commit remains the persistent decision boundary.
- **Independent promises:** result/readback/seal/history/reservation families are outside `completion_key`. Inventory continues protecting their dependencies even if a phase promise retires. Logical retirement can reclaim zero bytes; physical removal remains disabled.
- **Dependency integrity:** an old validation cannot qualify a newly written processing/prepared table. Completion acknowledgment must preserve first active provenance; it must not silently overwrite an incompatible dependent completion. Legacy evidence uses native admission/processing ordering and refuses missing or newer admission, preserving unknown provenance as a refusal.
- **Bounded work:** request and task state use shared Budget admission. Retirement appends one receipt plus compact per-generation markers; lifecycle history limits still apply. It adds no payload scan or persistent worker registry. Inventory still scans bounded lifecycle history, and historical receipts/markers accumulate; no scalability or latency improvement is established.
