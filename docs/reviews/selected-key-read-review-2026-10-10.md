## Patch summary

`changed_keys` resolves the ordered key names against each endpoint schema. Each changed file carries its matching endpoint's selected column indices. The function calls `OccurrenceScan::read_projected_file` and renames the selected arrays to `k0`, `k1`, and subsequent key names without selecting by the original indices a second time. The new integration fixture exercises reversed, non-leading composite keys through incremental joins and grouped summaries.

The concrete simplification is reuse of the existing selected-reader implementation. The patch removes the full-row-to-key array selection from this caller and introduces no separate decoder, schema conversion, default synthesis, or query execution component. It narrows the requested native fields; it does not establish a measured reduction in elapsed time or total bytes read.

## Data flow and invariants

**Key ordering is preserved end to end.** The old indices and `key_schema` come from the same ordered `keys` slice. New indices are independently resolved against `new_scan.schema()`. The selected reader may arrange native reads by native root order, but its output mapping restores the requested order. Consequently, using `batch.columns().to_vec()` is necessary: applying the original indices again would either select the wrong key or go beyond the smaller returned batch. Both consumers interpret `k{i}` using that same caller order. [incremental.rs:327](/Users/mikewolfd/Work/spicy-stack/docspec-rs/src/engine/incremental.rs:327), [incremental.rs:367](/Users/mikewolfd/Work/spicy-stack/docspec-rs/src/engine/incremental.rs:367), [incremental.rs:439](/Users/mikewolfd/Work/spicy-stack/docspec-rs/src/engine/incremental.rs:439), [selection.rs:78](/Users/mikewolfd/Work/spicy-stack/docspec-rs/src/storage/selection.rs:78)

**Types, defaults, and nulls retain the shared reader's rules.** The output key fields are cloned from the old schema and made nullable, while incremental admission requires equal public endpoint schemas. The patch neither casts selected arrays nor substitutes null values. Native field-ID selection still passes through the existing schema/default transformation, including the reserved file field used to retain the native transformation when a selected field is absent from an older file. The shared selection code then removes the transient file field and returns the requested columns. Default compatibility restrictions remain in the shared schema validator. **Affected keys remain conservative.** Discovery still emits keys from every row of both removed and added files. It does not cancel equal old/new key tuples before identifying affected groups. This matters when a row changes its non-key value, or a duplicate-key group's multiplicity shrinks while its key survives. Both must still trigger recomputation. Null-safe membership retains partial-null groups independently of the final join's declared null-matching policy. Equivalent logical representations and the metadata-only global-key sentinel retain their existing paths. ## Test behavior and edge cases

The new fixture writes the changed source in physical order `[text, a, b]`, uses declared join and summary keys `[b, a]`, and keeps the other join source in its existing `[a, b, text]` order. It therefore detects confusing physical positions with returned selected-column positions. Its replacement shrinks the duplicated `(1, 2)` group, changes a partial-null key's text, and inserts a new partial-null group. Both full setup outputs and incremental results are checked. [selected_keys.rs:9](/Users/mikewolfd/Work/spicy-stack/docspec-rs/tests/related_refresh/selected_keys.rs:9), [selected_keys.rs:90](/Users/mikewolfd/Work/spicy-stack/docspec-rs/tests/related_refresh/selected_keys.rs:90), [selected_keys.rs:139](/Users/mikewolfd/Work/spicy-stack/docspec-rs/tests/related_refresh/selected_keys.rs:139)

The join oracle enumerates source occurrences and compares direct Rust key values; reversing the order of the two equality conditions does not weaken that oracle. The shared checker compares output values and exact occurrence evidence. The summary checker independently builds a `(b, a)` count map, rejects duplicate output groups, and compares the complete sorted contributor-address list. These checks would expose missing affected groups, swapped key columns, lost duplicate multiplicity, and incorrect retained contributor addresses. They share the existing full occurrence reader with the application, so they are independent of the changed selected-read path, not an independent native-format implementation. ## Conclusion

The change is a small, appropriate reuse improvement. It preserves the affected-key relation and delegates ordered native reads to the maintained shared reader. Runtime qualification remains with the executing owner. Keep any performance claim limited to requesting fewer native fields until measurements establish wider gains; endpoint inventory work, changed-row key writes, and complete affected-group recomputation remain unchanged.
