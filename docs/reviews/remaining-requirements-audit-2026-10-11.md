## Remaining-column interpretation

- R1 "complete occurrence/value identity and evidence semantics" is too broad to be a next task. Existing occurrence, receipt, original-execution and exact oracle evidence cover supported paths. Pin remaining identity work to a specific rebuild/schema/history invariant and the UR-04 failure case. Broader disaster durability is required only for the declared failure profile; product loss/recovery targets remain explicit (R1:21, R7:15), not an implied universal power-loss/failover requirement.
- R3 stable field meaning across retained schema versions is accepted (R3:13); STATUS's full-rebuild renumbering/correspondence limit deserves a concrete same-field rebuild case. Arbitrary nested/type evolution, related-output edits and nested computed values are scope extensions unless a promised supported case requires them. R3:31,65 expressly require supported-rule qualification, not automatic arbitrary widening.
- R4 broader types/mappings and portable trust need scoped supported-reader evidence; R4:23 permits full fallback/refusal for unsupported accelerators, and :15 rejects caller-supplied trust. Scaling/failure qualification is required, but a universal certificate system is not.
- R5 evidence-dependent affected checks and honest reuse are explicit requirements (R5:21, T05). More aggregate functions/key types or computed groups as join inputs are not unconditional completion criteria: R5:17 scopes the first supported rules and permits full rebuilding/refusal. Arithmetic deltas/general incremental SQL are expressly later/deferred (:23).
- R6 contributor-table compaction and selected representation-authority retirement should be justified by the promised retained layout and a failing reclamation/cost case. Typed compaction with required evidence must remain exact; expanding every representation is not independently a universal task. Automatic orphan sweeping/recurring cleanup and default policies are explicitly deferred (R6:37,55,57).
- R7 "wider Dagster route" and "arbitrary crash-boundary" wording overstates the accepted ask. PLAN wants a thin selected executor with stable IDs/status and real loss recovery; adapters/dagster/README.md explicitly allowlists operation routes. Qualify each promised route and the useful retained boundaries, rather than every internal instruction. Native commit uncertainty and Q6 old actors still require exact evidence.

The efficient completion path is to replace vague "broader" work with the exact missing accepted fixture/invariant and its named consumer/product target. Keep unsupported behavior visible; do not turn that visibility into an obligation to implement every type, function, route, cache or scheduler.
