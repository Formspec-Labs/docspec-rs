## Patch summary

`admit_stream` shares one maintenance read guard between the owned opening task and the returned stream. The stream also owns an Engine clone, preserving host ownership while a consumer may request more data. The last EOF poll drops that retained state even if the exhausted stream object remains allocated (`src/engine/worker.rs:159`).

Engine group/evidence/combined reads first check that the supplied pin exactly equals an available retained result or completed readback in this host's catalog (`src/engine/read.rs:44`). They then use the existing immutable-manifest resolution and native reader. Comparison performs the same checks inside `admit_work`, keeping the complete finite computation alive if its caller disconnects (`src/engine.rs:513`).

The README explains shutdown, retired-result refusal and independent-reader availability (`README.md:187`). Independent free readers and verifiers acquire no producer-host lease (`src/engine/read.rs:103`; `src/engine/backfill.rs:149`; `src/engine.rs:2135`, `:2165`, `:2179`). The combined reader's new free entry point states caller-retained files or a published availability window explicitly.

## Data flow and invariants

**One guard, continuous ownership.** `admit_stream` creates `Arc<OwnedRwLockReadGuard<()>>` before spawning. One clone enters existing `Admitted`; the other moves into the opening closure and finally the outward stream (`worker.rs:175`, `:181`, `:188`). There is no unprotected handoff and no second read-lock acquisition behind a queued writer. If opening returns an error, both copies drop after normal task completion. If the caller cancels during opening, the task still owns its copies; its unobserved returned stream is dropped on completion.

**A live consumer keeps its selected bytes protected.** Unfold stores `(stream, guard, engine)` and moves the tuple through each polling future. A pending poll, an emitted batch and an error item all retain state until the next EOF poll or outward drop (`worker.rs:187`). Keeping admission after an error item is conservative: callers may still hold/poll that stream. EOF releases the tuple. A consumer cannot request further native work after dropping the only outward stream.

**Availability is checked inside exclusion.** Reader acquisition holds shared maintenance ownership before `check_read_release` checks retirement. Logical retirement requires exclusive ownership (`src/engine/retention/retirement.rs:385`). Thus retirement either completes first and the new reader refuses, or the reader obtains protection and retirement waits. Dataset locks serialize the exact completion lookup but do not remain held while streaming. Availability retirement collects every ordinary and Backfill readback for the operation (`src/engine/retention/availability.rs:220`, `:228`), so the operation-level check fences every accepted completion kind.

**Completion is independent of selection.** Ordinary execution commits `readback/<operation>` after serialized readback, then reaches the injected stop and selection boundary (`src/engine.rs:1459`, `:1511`, `:1529`, `:1543`). Backfill computes its key from the serialized dataset digest (`src/engine/backfill.rs:696`), uses the identical digest in the manifest (`:739`), commits the readback and only then reaches the stop/selection boundary (`:765`, `:779`). The corrected helper's `backfill-readback/<id>/<manifest.digest>` lookup is therefore the writer's exact key, not a guessed history lookup. Full stored-pin equality prevents a caller from borrowing another composition's availability.

**One combined payload implementation preserves the budget and join semantics.** The extracted free function retains manifest resolution, hidden-field selection, source occurrence locators, inner joins on file/row occurrence identity and `query::bounded` (`backfill.rs:161`, `:170`, `:176`, `:183`, `:197`). Its `budget.context()` is the exact delegation previously supplied by `Engine::context` (`src/engine.rs:239`; `src/budget.rs:98`), preserving the shared native memory/spill runtime and query settings. The Engine passes its own lifecycle Budget after admission; the standalone caller supplies its own Budget and file-availability responsibility. No join algorithm, output allowance or Engine protection is bypassed by the extraction.

**No ordinary-read inventory scan was added.** The corrected check looks up a fixed list of exact keys and reserves decoded memory for one record at a time (`read.rs:74`, `:83`; `src/catalog.rs:63`). It does not enumerate namespaces, expand retained dependency graphs, hash payloads or call `inspect_retention`. The unchanged manifest resolution still checks the serialized selection (`engine.rs:2240`). A cold lifecycle view may load its native lifecycle rows; this review makes no constant-time or measured overhead claim.

**Comparison cancellation remains different from stream cancellation.** Comparison is a finite operation with a result still owned by the private task. It runs through `admit_work`, retaining its Engine and guard until computation returns (`engine.rs:523`; `worker.rs:111`). There is no need to add a second comparison worker or alter its duplicate-aware query.

## Native cancellation evidence

Dependency paths below refer to the inspected installed sources under `/Users/mikewolfd/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/`. Their versions match `Cargo.toml`.

1. DocSpec's group/evidence reader calls the maintained Iceberg reader with data-file concurrency one (`src/storage.rs:82`). Iceberg implements that path as `tasks.and_then(process).try_flatten`, owned by the returned stream (`iceberg-0.10.1/src/arrow/reader/pipeline.rs:64`). It opens a `FileIO::new_input` and a reader (`pipeline.rs:419`); range requests call `FileRead::read` (`reader/file_reader.rs:57`). No output file or catalog mutation occurs in this path.
2. Iceberg does spawn delete-loading work. It decodes delete files, updates a private `DeleteFilter`, and sends its result through a oneshot channel (`iceberg-0.10.1/src/arrow/caching_delete_file_loader.rs:168`, `:191`, `:214`, `:229`). The equality-delete helper updates in-memory state and wakes waiters (`arrow/delete_filter.rs:242`). These are interpretation of source delete records, not object deletion. A late read error or ignored send after outward cancellation cannot create a new retention claim.
3. DocSpec's DataFusion provider owns `NativeSource`, schema and Budget, and produces native read streams (`src/query.rs:95`, `:107`). It holds no Engine or Lifecycle handle and invokes no retained-object writer. The combined query is a SELECT over these providers (`src/engine/backfill.rs:176`, `:199`).
4. DataFusion's receiver stream owns a join set, cancels producer tasks when dropped and stops input forwarding when its output channel disappears (`datafusion-physical-plan-53.1.0/src/stream.rs:54`, `:122`, `:334`, `:356`). A started blocking task may continue until completion/error (`stream.rs:285`); that fact alone does not establish a retention violation.
5. The HTTP encoder is demand-driven and explicitly creates no producer task/queue (`src/http/ipc.rs:77`). Once a batch has been encoded, its transferred chunk owns the bytes. Neither a pending socket write nor a held Arrow batch needs the original immutable source file for later decoding.

**Conclusion from the trace:** after outward EOF/drop there is no remaining consumer entitled to more batches from that read, and the traced late work cannot publish or mutate managed object paths. Releasing maintenance admission is correct. On Unix, already opened source handles may continue to read an unlinked inode; a later unopened path may fail. Either is harmless to the canceled read's abandoned output. Platform deletion refusal would be handled by the future removal service's per-object outcome, not by draining every canceled reader.

Stronger custody becomes necessary if a future reader adds an externally visible output callback, persistent cache writes into the removal namespace, retained-result publication, mutable source repair, or a separately live consumer that outlives the wrapper. Those are concrete change triggers. Private DataFusion spill/scratch work and native read-only tasks are not authority to publish or recreate managed objects. This review does not claim immediate cancellation, zero residual I/O or that every internal native allocation is released at outward drop.
