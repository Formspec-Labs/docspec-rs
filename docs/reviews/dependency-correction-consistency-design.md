# Dependency correction: consistency design review

**Verdict: APPROVE a scoped correction and supplemental association in the existing lifecycle.** Preserve immutable computation records, qualify a new association against the corrected material dependencies, and recheck that qualification in the guarded selection commit. The existing dataset-wide `invalidate` operation is a useful broad refusal mechanism; it does not complete Q4.

Reviewed October 10, 2026, against `582ea804d0be273037092459ad72b2ab69453532`. This is an independent static review of Q4, R3, the plan, status, and the implementing seams. No Cargo commands, tests, builds, benchmarks, corpus reads, or payload hashes ran. Only this report changed. The author owns implementation and execution evidence.

## Findings requiring implementation

### F1 — A dataset-wide epoch cannot be the correction's scope

**BLOCKER to Q4 qualification; intent versus shape.** `invalidate` increments `Authority.eligibility` and records only a reason (`src/engine.rs:695–742`). That epoch participates in general phase keys and scalar file, prepared, and validation keys (`src/engine.rs:1958–2003`, `src/engine/backfill.rs:1062–1067`, `src/engine/backfill/preparation.rs:40,216`). New scalar admission also refuses the entire selected source after that epoch changes (`src/engine/backfill.rs:520–524`). Consequently, using this operation alone can refuse a stale selection but cannot preserve unaffected qualified work in the same dataset.

**RESHAPE:** record the omission against the deficient material declaration/definition, with an exact retained identity and revision, in the existing lifecycle table. Keep the global eligibility guard for broad invalidation. Consult the applicable correction at reuse and selection without changing unrelated material keys. Q4 explicitly requires unaffected reuse; R3 requires precise invalidation (`docs/requirements/07-operations-qualification.md:109–115`, `docs/requirements/03-schema-backfill.md:17–19,53–59`).

### F2 — Historical generation and new qualification need distinct records

**BLOCKER to Q4 qualification; named seam.** `PhaseDependencies` identifies recovery inputs, while `ComputedGroup` describes a group's binding to the current source/request (`src/model.rs:494–505,828–839`). Scalar file completions retain source bytes and optional original schema metadata, but lack a separate supplemental declaration (`src/engine/backfill.rs:37–47`). The current binding verifier expects the original authored expression and its inferred inputs (`src/engine/backfill/verification.rs:380–431`). Neither a reason string nor changing that original binding can describe an honest correction.

**RESHAPE:** keep the original dependency declaration, execution, output, and native completion generation unchanged. Add a supplemental qualification to the *new association*, identifying the selected original result, target source/occurrence scope, corrected declaration, exact supporting retained evidence, and the check that established correspondence. Reuse the existing manifest/group binding and completion machinery; do not add a parallel result registry. A dependency declaration is not proof of actual field use, and adding language now must not claim it was recorded at execution time (`../DocSpec/docs/core-model.md:128–136,229–237,265–287`).

### F3 — Prepared results and readback must not bypass the new check

**BLOCKER to Q4 qualification; consistency boundary.** General selection, scalar selection, and refresh selection each perform their final authority checks after preparation (`src/engine.rs:1723–1770`, `src/engine/backfill.rs:819–854`, `src/engine/refresh.rs:226–270`). Retained readback deliberately skips earlier preparation (`src/engine.rs:1247–1285`, `src/engine/backfill.rs:599–623`). Checking correction state only in file lookup therefore misses a supported resume route.

**KEEP** completed preparation and readback. **RESHAPE** final selection to check the candidate's applicable declaration/qualification references against fresh lifecycle state under the existing locks and expected native snapshot. Centralize the shared local check near `select_with_progress` (`src/engine/history.rs:160–233`), with early lookup checks for useful refusals. The check must include inherited affected groups, not only the newly computed target. A compatible sibling selection must not carry an unqualified affected group forward. A conflict reloads applicable correction state; it cannot merely retry a cached acceptance.

### F4 — The existing dependency test does not exercise the required event

**CONCERN; proof scope.** `dependency_correction_fences_adoption_without_output_change` pauses a first build after processing, globally invalidates, and observes refusal (`tests/lifecycle.rs:582–608`). It has no prior classification being reused, no changed language input, and no supplemental or unknown-input branch. The backfill invalidation test likewise proves broad refusal (`tests/backfill.rs:418–476`). The status correctly leaves Q4 unfinished (`docs/STATUS.md:1250`).

**RESHAPE the acceptance fixture:** establish a genuinely reusable result with an inadequate text-only declaration, select it for a new association, then pause after that lookup. Record the language omission while the pending target and selected head remain otherwise unchanged. Resume the real selection path. Merely editing SQL is insufficient: current SQL inputs are inferred from the expression tree, and the scalar file key already includes the complete source `ObjectRef`, so changing language bytes in that file normally misses reuse before any correction is recorded (`src/engine/backfill/expressions.rs:80–96,133–157`, `src/engine/backfill.rs:1062–1067`). The implementation note below gives a production-path fixture using omitted semantic applicability and a virtual language field; it needs no forged completion or general adoption path.

## Smallest correct design

1. **Record the omission independently of its resolution.** Accept a bounded typed correction with a stable retry identity, exact deficient declaration/definition identity, added material dependency descriptions, and reason. Commit it under the affected dataset lock with the existing native compare-and-swap behavior. Persist it even when historical evidence is missing. An identical retry reconciles the same correction; a conflicting retry refuses. Recording the correction does not overwrite prior computation or imply failure of its historical execution.

2. **Resolve one applicable correction state.** Directly look up the scoped correction using the lifecycle snapshot. Capture its exact identity/revision, including an explicit no-correction state when absent. A later correction must be visible to the final selection check. Use existing budgeted metadata reads; no process-global correctness cache, dataset enumeration, or payload scan belongs in this check. A broader correction must also cover the previously deficient declaration so callers cannot escape by reusing its old identity.

3. **Qualify the new association.** The original result remains an input to this decision. Adequate evidence must establish the added dependency's historical meaning/value or other justified correspondence with the target, at the affected scope. Stable field IDs, exact retained sources and occurrence correspondence matter; same business key, equal output, a current language value, or a sampled match is insufficient. When all corrected dependencies correspond, retain a supplemental declaration and the existing output generation in the new group binding. When they differ, refuse that reuse or perform affected recomputation. When historical language is unknown, keep it unknown; a fresh, adequate revalidation can qualify the *new* association without claiming the original execution observed that value. Otherwise recompute with the corrected inputs. Nothing in Q4 requires revalidating unaffected source data, groups, or ordinary reads.

4. **Make final selection decisive.** Check the assembled candidate against current scoped correction state in the same lifecycle view used for its guarded selection. Require a qualification covering every applicable omission and its exact selected result/target. A changed correction refuses or causes renewed qualification of affected work; unrelated catalog changes only require fresh metadata decisions. Preserve original phase/readback records even when adoption fails, matching `check_completion`'s existing distinction between retained completion and promotion (`src/engine.rs:1793–1808`). Exact replay of a previously committed historical result remains a replay, not a fresh reuse decision.

5. **Retain the evidence once.** Attach required object/native references to the existing protected completion/result records and independent manifest representation. Inline bounded facts are sufficient when they honestly express the evidence; larger correspondence data belongs in existing native relations, not per-row lifecycle records. Ensure new supplement fields survive strict inventory decoding and catalog-free inspection. Do not equate physical-retention dependencies with the narrower material dependency statement (`src/model.rs:494–505`; `../DocSpec/docs/core-model.md:152–171`).

The exact record names are an implementation choice. The necessary concepts are the immutable original declaration/result, a current scoped omission, and a retained qualified association. A second mutable source of truth, general plugin framework, or new validation workflow is unnecessary.

## Invariants and falsifiability

| Invariant | Status in proposed design | Failure if broken |
| --- | --- | --- |
| One guarded catalog decision selects the complete result (`docs/PLAN.md:23–33`) | PRESERVED; current correction lookup uses that same decision boundary. | A correction committed after lookup is ignored. |
| Original execution/declaration/generation survives (`Q4`; Core §6.3/§7.4) | PRESERVED; supplement belongs to the new association. | History falsely says language was recorded or a reused value was generated again. |
| Unknown remains unknown (`Q4`; Core §6.3) | RELIED-UPON; no inference from current input. | Missing historical language becomes fabricated provenance. |
| Unaffected work stays reusable (`R3:17–19`; `Q4`) | PRESERVED; scope controls checks, not a new dataset-wide epoch. | A correction to classification rebuilds independent groups. |
| Retention follows actual bindings (`R1:31–36`; Core §5.2) | RELIED-UPON; supplement evidence receives ordinary protection. | A selected association outlives the evidence supporting it. |

**User value:** classification correction prevents incorrect reuse while retaining unrelated expensive work and a readable historical account. The added conceptual cost is scoped correction metadata and one explicit qualification binding; it pays down ambiguity in the current global reason string. No speed claim follows from this static review.

**Counterfactuals:** retaining only global invalidation is smaller but fails unaffected reuse and cannot explain supplementation. Rewriting historical declarations appears simpler but violates preservation and conceals uncertainty. Removing the commit-time check permits the exact Q4 race even with correct lookup. Existing retirement records cannot subsume the correction: retirement ends availability/recovery promises, whereas an omission changes correspondence eligibility and must retain history. Reject this design if a paused stale adoption can select, an unsupported supplement can qualify by current values alone, or unaffected work recomputes solely because a sibling declaration changed. A future reviewer should also reject a solution whose growing correction history causes an unbounded scan on every ordinary read.

## Final assessment

Intent and proposed shape match Q4. The user-value claim is supported by the explicit acceptance scenario. Existing catalog, completion, protection and manifest machinery partially subsumes the work; the missing part is scoped dependency correction and honest supplemental association. Confidence is high in the requirement/implementation gap and consistency boundaries, medium in exact API placement until the implementation exists. No architecture reversal, wholesale revalidation, or second registry is justified.

## Implementation note: production-path fixture and sufficient evidence

**An omitted semantic applicability condition gives a legitimate existing-path Q4 fixture. No new adopter is needed.** Use an English-specific text classifier whose SQL reads only text but whose output meaning is valid only in its language context. Its SQL field inference is complete; its declared material conditions are inadequate. Language is material because it changes interpretation, not because the compiler missed a column access (Core §4.1, `../DocSpec/docs/core-model.md:92`). This distinction supersedes the earlier review suggestion that the fixture needed an explicit historical-completion lookup capability. Keep supplemental applicability fields separate from `ComputedGroup.input_fields`; do not misrepresent them as actual SQL field access.

The simplest genuine **file-completion** race uses these existing production steps:

1. Build a text source and use `evolve_schema` to add virtual language with default `en`. Retain its actual source metadata and stable text/language IDs.
2. Run the English-specific, text-only group with `backfill_until(..., "files")`. This computes real output and retains its real `FileCompletion`, including the original source metadata, before whole-group assembly or selection (`src/engine/backfill/preparation.rs:95–98,165–168`). The group need not be selected for its completed file to be reusable.
3. Select a schema that keeps text, hides the old language field, and adds fresh same-name language with default `fr`. The field builder retains selected IDs, removes the omitted field and paired marker, and assigns new IDs for additions (`src/engine/schema.rs:427–501`). Schema preparation preserves source objects (`src/engine/schema.rs:170–193`). Its writer-definition change happens **before** the pending adoption is admitted.
4. Admit a new backfill against that already selected French source, using its current source definition and the same `GroupDefinition`. The file key uses unchanged source `ObjectRef`, text-only expression dependencies, and unchanged eligibility; it excludes the enclosing source writer definition (`src/engine/backfill.rs:1062–1067`; `src/engine/backfill/expressions.rs:136–157`). Therefore production file lookup finds the actual original completion (`src/engine/backfill/preparation.rs:74–83`).
5. Pause immediately after that hit, record the scoped omission, then resume. Keep selected head, source boundary, writer definition, and global eligibility unchanged during this pause. Require a correction-specific refusal at adoption and an unchanged no-correction control that reaches selection. The original unfinished backfill does not create a source-admission gap: backfill admission preserves the covered boundary (`src/engine/backfill.rs:555–589`), and the gap checker excludes backfills (`src/engine/retention.rs:74–82`).

If the original English group was already **selected**, the French schema operation prepares all selected groups and can create a prepared completion for the French source (`src/engine.rs:1503–1543`). A later same-definition backfill then hits `backfill-prepared` before reaching file lookup (`src/engine/backfill/preparation.rs:32–54`). That is still a valid prepared-reuse race, but it must not be reported as a file hit. Stopping the original group after files avoids this interception without deleting or forging metadata. Qualify the prepared/readback routes separately.

The sufficient-supplement rule can stay narrow: identical source `ObjectRef`, retained original source metadata, and the same supported primitive root field ID with the same material read interpretation for each added applicability field. Include type, requiredness, initial default, and supported observed metadata; share the existing normalization where appropriate (`src/engine/backfill/expressions.rs:136–157`). In the positive fixture, both interpretations establish the same virtual `en` language on the same original file. Retain that added statement and the original completion generation in the new association. No payload comparison or replacement completion key is needed. A changed future write default does not change historical file values (`src/model.rs:782–784`). A replaced language ID, different initial interpretation, missing original field, or absent `source_metadata` refuses correspondence. Do not claim that changing an existing field's initial default is supported: the native reader rejects that evolution (`src/storage/schema.rs:35–63`).

For the **unknown** fixture, compute and retain the same text-only classification before any language field exists, then add virtual language and admit the new backfill. The old file key can still match, but the original `source_metadata` has no language field. That is unknown historical language, not historical null or the later default. The new supplemental qualification must refuse; source metadata retained by a later assembly must not replace the original file completion's metadata. For the **adequate** fixture, keep the original language ID/read interpretation and reuse that exact file completion. Assert original record/output identity, no new computation, a new explicit supplement, and replay after restart.

These cases require only scoped correction state, retained applicability qualification, and the fresh selection check identified above. They qualify same-file correspondence, including a semantic condition absent from SQL inference. They do not qualify cross-file matching, arbitrary external classifiers, or a general historical repair mechanism. Re-running the same English-only definition on a known French target does not resolve the applicability failure; the supported remedy must qualify a suitable definition or refuse.

## Author-design follow-up

Reviewed `docs/dependency-corrections.md` on October 10, 2026, without execution or source edits. **APPROVE the bounded direction**, subject to these concrete implementation corrections. The design correctly separates SQL usage from applicability, retains original per-file origins, checks every included group at selection, and uses a real same-file Q4 fixture (`docs/dependency-corrections.md:17–34,42–58,71–90,109–128`). This approves a design, not Q4 implementation.

- **Bind the generation actually consumed during concurrent completion.** `acknowledge_files` skips a material-key write when another attempt already won, while assembly retains the current attempt's previously consumed outputs (`src/engine/backfill/preparation.rs:123–149,337–374`). An origin descriptor populated by subsequently looking up that key could therefore name the winner's generation while the prepared group contains the loser's physical outputs. Resolve and retain the exact original record/revision before adopting its files, or retain the actual consumed attempt separately. Do not attribute current bytes to whichever record now occupies the reusable key. Add a concurrent same-key completion case proving each prepared output's descriptor, origin operation and generation agree; include warm and reopened metadata resolution. This is required to implement the plan's “actual file-completion generations” promise (`docs/dependency-corrections.md:45,48–52`).
- **Choose the corrected-readback retry identity explicitly.** General resume loads one `readback/{operation}` and immediately proceeds toward selection (`src/engine.rs:1247–1288`); scalar resume permits multiple readbacks but rejects any difference in the target's full `ComputedGroup` binding (`src/engine/backfill.rs:935–942`). A supplemental association changes that binding even when outputs and original execution are unchanged. Either require a fresh operation after a cached readback is fenced, reusing its qualified computation, or introduce a distinct immutable association/readback generation and compare original output/origin separately from supplemental qualification. Preserve existing corruption checks for different outputs or original generations. Do not overwrite the old single slot, repeatedly return an unqualified old manifest, or treat every changed binding as harmless. Add adequate-supplement-after-readback and second-correction-after-readback cases for the chosen behavior (`docs/dependency-corrections.md:85–90,125–128`).

No broader adopter, descendant scan, source-only consumer invalidation, or ordinary-read requalification is needed. Minor document correction: the Q4 link at `docs/dependency-corrections.md:4` should use the existing `#q4-discovered-dependency-omission` anchor.
