# Dependency utilization audit

**Keep the pinned package family. Finish native column selection in changed-key discovery, reuse captured metadata, remove a redundant join scan, and then qualify native Parquet layout.** The stack already delegates parsing, columnar operations, execution, storage formats, HTTP, scheduling and hashing to maintained packages. No direct dependency inspected here warrants replacement or blanket feature expansion.

This source-only audit checked HEAD `2a5ae513cb0aa7c40f771a534474956ca92364c8` and the working tree on 2026-10-10. It reuses the [original package audit](../dependency-efficiency-audit-2026-10-10.md) and [follow-up](dependency-audit-followup-2026-10-10.md), rechecks the active call sites, and supplies complete direct-package coverage without repeating their full upstream analysis. Rust review guidance was applied to dependency boundaries, allocation and resource ownership. No builds, tests, benchmarks, dependency changes, corpus reads, cleanup or source edits were performed. Only this report was written. The unrelated change-chain implementation review was excluded.

## Decisions and minimum qualification

These are ranked by likely user value, with a small independently useful cleanup identified separately. Code facts establish removed work; elapsed-time, resident-memory and disk benefits remain hypotheses until measured.

| Rank | Verified current work and concrete next change | Minimum qualification before claiming the benefit |
| --- | --- | --- |
| **1. Read only keys during incremental discovery — additional call-site omission.** | [changed_keys](../../src/engine/incremental.rs#L318), called by [incremental joins](../../src/engine/incremental.rs#L153) and [aggregates](../../src/engine/aggregation.rs#L201), uses `read_file` and only afterward selects key columns at [line 435](../../src/engine/incremental.rs#L435). Pass key indices to the existing [read_projected_file](../../src/storage/occurrences.rs#L362), which sets native `project_field_ids`. Rename/share the returned selected columns directly; do not apply the original full-schema indices a second time. This uses the already qualified selection adapter and maintained Iceberg/Arrow reader, avoiding unrelated payload decoding. | Resolve key indices against each captured schema and preserve key order, `kN` names, types, nulls, complete-file row checks and sequential consumption. Preserve the empty-key metadata-only branch and equivalent-representation no-op. Exercise non-leading/reordered composite keys, defaults, old/new schema qualification, join and aggregation callers, and a damaged unrequested payload column. Use existing native metrics to establish requested-byte savings; elapsed time and peak memory remain unmeasured. |
| **2. Reuse captured native metadata within one immutable operation.** | [Located query execution](../../src/query.rs#L317) calls [ordinary occurrence opening](../../src/storage/occurrences.rs#L65), which calls [snapshot_files](../../src/storage.rs#L519). That walks all retained snapshots and unique manifests, then occurrence capture plans tasks again. Reuse an admitted `Arc<OccurrenceScan>` through the existing [captured-file provider](../../src/query.rs#L77) when the caller already has that exact capture. Reuse the existing `Table` and parsed metadata as well. With K executions over H snapshots/M unique manifests, this removes repeated O(K(H+M)) inventory work in favor of one capture plus replay. This is a structural inference, not a timing result. | Prove exact pin, snapshot, schema, file membership, field/default interpretation and occurrence identity remain equal. Keep the capture and all metadata admission alive until its final reader drops; exercise cancellation, failure and concurrent reuse. Count actual inventory/planning calls, opens and bytes while varying repeated execution and retained history independently. Retention/admission still require their complete historical closure. No new general cache. |
| **3. Avoid reading the large relation to prove an already unique join side.** | [join_plan](../../src/engine/refresh.rs#L532) executes each probe before the main query. [join_queries](../../src/engine/refresh.rs#L642) currently semi-joins the constrained side against the other input, then groups duplicates. First use maintained DataFusion grouping to test the constrained side alone. If unique, its matches cannot fan out; skip that probe's other-side scan. If duplicates exist, retain the matched-key proof. [DataFrame aggregate/join APIs](https://raw.githubusercontent.com/apache/datafusion/53.1.0/datafusion/core/src/dataframe/mod.rs) already supply the operations. | Preserve unmatched-duplicate acceptance, composite/partial-null keys, both null modes, every join kind and self-join roles. Existing [fanout-before-write](../../tests/related_refresh.rs#L410) and [unmatched duplicate](../../tests/related_refresh.rs#L771) fixtures establish the required distinction. Verify plans/read counters show the large-side scan disappears on the unique branch; measure the added constrained-side pass in the duplicate branch. No durable key index. |
| **4. Qualify native row-group layout independently of input batch size.** | [Native writer](../../src/storage.rs#L264) sets the row-group row limit to `batch_rows`. The maintained [Parquet properties](https://raw.githubusercontent.com/apache/arrow-rs/58.4.0/parquet/src/file/properties.rs) already expose separate row and estimated encoded-byte limits. [Flat exports](../../src/engine/export.rs#L482) already use `ArrowWriter::memory_size()` and `flush()`. Larger native groups may reduce footer/file overhead and improve compression, but can increase writer and subsequent reader memory. | First establish large-row-group/small-batch read behavior with wide and nested values. Preserve field IDs, nullability, defaults, stored origins and independent exact readback. Compare native output/footer size, requested range bytes, write/read time, process memory, peak additional disk and retained bytes, including failed attempts and old/new coexistence. The flat-export result does not qualify native layout. |
| **Small cleanup; can precede the larger work.** | [Origin checks](../../src/engine/backfill/origins/checks.rs#L249) still use `.metadata((*metadata).clone())`. The pinned [TableBuilder setter](https://github.com/apache/iceberg-rust/blob/v0.10.1/crates/iceberg/src/table.rs#L74) accepts `TableMetadataRef` (`Arc<TableMetadata>`): pass the shared value. [Request fingerprint](../../src/engine.rs#L2061) and [physical schema identity](../../src/storage/inspection.rs#L50) still allocate JSON solely to hash it; route the unchanged normalized values through [json_digest](../../src/storage.rs#L56). | Preserve admission lifetime, readonly mode and exact metadata association. For JSON, compare frozen old/new digests and error propagation, including Unicode and schema normalization. This removes a deep metadata clone and one O(J) temporary byte vector per hash call; it removes no payload scan or disk write. These are the existing follow-up findings, still open. |
| **Qualification support, attached to the changes above.** | Readers immediately discard the maintained scan result's metrics when taking [`.stream()`](../../src/storage.rs#L131). Retain a cloned [Iceberg `ScanMetrics`](https://raw.githubusercontent.com/apache/iceberg-rust/v0.10.1/crates/iceberg/src/arrow/scan_metrics.rs) handle in the qualification path instead of adding another decoder or counting payload pass. | The counter adds requested range lengths before I/O; it is not physical disk traffic, successful-delivery bytes, or manifest-planning traffic. Check completion, failure and early-drop interpretation, and count planning separately. This enables evidence, not faster execution by itself. |

Within rank 2, [open_pin](../../src/storage.rs#L714) also hashes metadata with `verify_object` and then reopens it through `StaticTable::from_metadata_file`. Prefer reusing an already verified immutable handle first. A bounded single read can hash and deserialize the same uncompressed JSON bytes before building a readonly table. Preserve digest/length, snapshot/schema checks, input and decoded-memory admission, and refusal behavior. The pinned [TableMetadata reader](https://github.com/apache/iceberg-rust/blob/v0.10.1/crates/iceberg/src/spec/table_metadata.rs#L450) also recognizes gzip; plain `serde_json::from_slice` is not an equivalent replacement for compressed metadata. Keep the maintained compressed path until its decoding/admission is qualified.

The existing table clone shares Iceberg's cache, but `snapshot_files` explicitly loads manifest lists and manifests outside that cache. Merely retaining a `Table` therefore does not remove those loads. The pinned [cache weigher](https://raw.githubusercontent.com/apache/iceberg-rust/v0.10.1/crates/iceberg/src/io/object_cache.rs) uses the size of the owning structs rather than their heap entries. Its configured capacity is not a complete heap bound. Keep reuse scoped and admitted instead of treating a larger Moka cache as the solution.

| [Independent exact comparator](../../experiments/comments-e2e/oracle.py#L97) | An independent implementation is the qualification boundary. Reusing production output as its own expected answer removes the check; these scans are intentional. |

Keep reader concurrency/range coalescing/footer-prefetch tuning deferred until repeated work is removed and the actual storage adapter is measured. Iceberg already exposes these [reader controls](https://github.com/apache/iceberg-rust/blob/v0.10.1/crates/iceberg/src/arrow/reader/mod.rs); one active file does not mean one active range request. Do not infer a whole-process memory ceiling from batch rows, a spill directory, or cache capacity. The [existing pinned spill-quota fixture](../../src/budget.rs#L256) also records accounting retained after an overrun until runtime reopen; this audit neither fixes nor executes it.

**Preserve bounded input activation when composing more streams.** Pinned [UnionExec](https://raw.githubusercontent.com/apache/datafusion/53.1.0/datafusion/physical-plan/src/union.rs) exposes the sum of its input partitions; [CoalescePartitionsExec](https://raw.githubusercontent.com/apache/datafusion/53.1.0/datafusion/physical-plan/src/coalesce_partitions.rs) starts a task for every input partition and sizes its channel to that count. `compute_threads` is not a universal live-reader cap. Existing [sequential `try_flatten`](../../src/query.rs#L368) demonstrates the smaller maintained composition when only one reader should be active. Future change-chain consumption must bound activated readers and retained buffers independently of chain length, exercise early-drop/cancellation and preserve exact results. This is a verified library integration constraint, not a finding that an unimplemented future path has failed.

**A later scalar-backfill candidate needs more than changing one call.** [File preparation](../../src/engine/backfill/preparation.rs#L609) also calls the full reader, but [Expressions::compile](../../src/engine/backfill/expressions.rs#L128) binds physical expressions against the complete schema and [evaluate](../../src/engine/backfill/expressions.rs#L186) locates occurrence columns by that schema's width. Reusing selected-column reads there requires compiling maintained expressions against the selected input schema and preserving field-ID dependency identity, metadata-sensitive functions and both occurrence columns. Qualify rename/default/null/constant-only cases and retained-reuse behavior. The avoided decode is plausible; this is a broader follow-on than the direct changed-key adoption and is not a safe one-line substitution.

Keep feature trimming and upgrades separate from runtime optimization. [Cargo feature unification](https://doc.rust-lang.org/cargo/reference/features.html#feature-unification) means root-default changes can leave the same features enabled transitively. Preserve the compatible Arrow/Parquet/Iceberg/DataFusion family, supported SQL functions and input codecs until a concrete measured build/capability decision justifies a change. [Rust toolchain](../../rust-toolchain.toml), [build job limit](../../.cargo/config.toml), [profiles](../../Cargo.toml) and [gate](../../scripts/check) already use maintained tools; test-target grouping addresses a known build-storage cost without new infrastructure.

For any resource claim, report scans/requests/bytes, process memory, scratch, peak additional disk and retained storage relevant to that change. Attribute build outputs separately from dataset amplification. Run the focused semantic checks and repository gate for implementation, then perform a controlled comparison only for the claims being made. This audit supplies source evidence and candidate changes; it supplies no new performance measurement.
