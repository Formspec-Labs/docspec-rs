# R2 consumer qualification: actual promise and next bounded case

Read-only audit of the current DocSpec Rust and nearby SpicyRegs source, 2026-10-11. No build, provider request, or shared source modification. Paths below are relative to `/Users/mikewolfd/Work/spicy-stack/`; line references name current source, not frozen external receipts.

## Decision

The smallest missing application qualification is **a DocSpec-produced immutable local flat export read through the actual SpicyRegs MCP HTTP `query_sql` path across correction and deletion, with an old connection held on its original file**. Existing export tests establish the producer substrate; existing MCP tests commonly replace the connection and therefore do not establish this producer-to-application path. This first fixture must remain explicitly a values/type/disclosure test. Full R2/Q8 also needs an agreed application binding from the export to its exact canonical release and evidence; the current unmanaged local reader has no such binding.

Do not replace that application test with another direct DuckDB/PyArrow comparison. Do not add a public publisher, universal reader, or a second generation authority to make a fixture look complete.

## What the requirements actually promise

`docspec-rs/docs/requirements/02-incremental-publication.md:13,35,46` requires a **named** consumer capability matrix before format freeze; application/browser/SQL/analysis/bulk are categories to identify, not five already-qualified clients. `07-operations-qualification.md:163` still names actual consumers, operating targets, disclosure and retention as product inputs. No document found freezes a complete SpicyRegs-to-DocSpec Rust format/type/evidence mapping.

The common requirements are exact immutable data/schema/evidence selection; channel resolution once; effective membership/deletes; bounded I/O; old-reader availability; and disclosure authorization for every reused byte, including hidden/deleted rows and metadata (`02-incremental-publication.md:15–23`). Evidence-only changes advance evidence without unnecessarily rewriting values (`:19`; `RESEARCH.md:29`). Q8 expressly requires corrections, deletions, evidence-only changes, downstream distribution/transfer, cold independent readback and interruption recovery; omitted stages remain unqualified (`07-operations-qualification.md:141–147`).

The first research delivery is fixed-schema Comments through subject **and receipt/evidence** preparation, publication and independent readback (`RESEARCH.md:35–39`). The representative Comments performance acceptance is defined in `PLAN.md:134–160`; current `STATUS.md:14–19,85–87` records passing scoped full local runs with exact independent readback. That passing local gate does not establish the separate SpicyRegs application handoff audited here.

SpicyRegs fixed-URL Comments exports are explicitly **not pinned**: a later query can see a newer object (`mcp_server.py:2011–2014`). They cannot satisfy the held-old-release requirement merely by checking a receipt/row count. Its saved native selection supports exact subjects/receipts in its own format (`spicy-regs/docs/native-generation-lifecycle.md:3–17,21–41`). A local directory without saved selection is explicitly `local-unmanaged`; a managed download verifies its publication selection and members (`spicy-regs/src/spicy_regs/local_data.py:91–143,201`). These are useful existing application mechanisms, not DocSpec Rust adapters.

## Existing proof worth reusing

- `docspec-rs/tests/exports.rs:155`: exact primitive Arrow values/types/nulls and authorized column order, including binary, decimal, temporal units/time zones. This tests the producer's supported subset, not MCP JSON representations.
- `tests/exports.rs:556`: only authorized columns and exact occurrences reach independent Parquet; private canary remains excluded.
- `tests/exports.rs:608`: correction replaces duplicate-key population, deletion removes active rows, null key remains, old export stays exact, retry reuses completed export, regressive export refuses.
- `tests/exports.rs:669,715`: empty schema/policy and durable export validation/selection recovery. Reuse these existing gates rather than reproduce their internals in a new test.
- `tests/evidence_updates.rs:229,437,544`: receipt-only updates preserve source/computed pins and duplicate/null occurrence identity; receipt lists preserve order/empty/null; related evidence-only refresh reuses values/contributors while coverage advances. `src/engine/evidence.rs:238,258` exposes separate receipt and source-occurrence reads; `src/engine/read.rs:43` exposes contributor evidence. Thus evidence-only local support exists, but export/MCP linkage is untested.
- `tests/http_read.rs:21,161,278`: exact historical values, bounded HTTP framing, empty stream schema and catalog-free CLI read. These cover DocSpec transport rather than the SpicyRegs application.
- `spicy-regs/tests/test_mcp_query_results.py:13–31` provides the real MCP HTTP tool-call harness, but its connection is monkeypatched to in-memory DuckDB. Keep the HTTP harness and replace that fixture setup with the real `_build_connection` over the export file; do not monkeypatch the reader/query result.

## Smallest next patch and acceptance

1. Add a tiny explicit local fixture driver in DocSpec's existing integration-test/qualification path, reusing the export fixture APIs: build duplicates, null key, null versus empty text, Unicode text, primitive numeric/decimal/temporal fields and a private canary; retain exact ReleasePin and ExportPin records. Produce immutable per-version export paths, then correction/delete and a third evidence-only release. Use the current export operation/channel APIs; never rewrite a previously exported object.
2. Add one SpicyRegs MCP integration test using those actual retained exported files and existing `TestClient(build_app())` tool-call helper. Configure the explicit local directory, establish the real connection for version A, keep it alive, construct version B separately, and query both through HTTP with deterministic ordering and enough result capacity to avoid truncation. Assert exact duplicates, null/empty distinctions, deletion, correction, authorized schema and application JSON values/type descriptions. Verify the recorded export identity before admission, without treating directory names/row counts as immutable proof. Producer process/workspace is not needed for the application read.
3. In that same fixture record the evidence-only release's distinct canonical version and unchanged public values. Check old and new exact receipt selections through existing DocSpec readers. Label this **separate evidence proof**, because MCP has not consumed/bound those receipts. This is the cheapest honest end-to-end application values checkpoint; it does not close Q8 or application evidence access.

To extend that checkpoint into full Q8, first agree the small application adapter: how an explicitly trusted ExportPin plus exact canonical release/evidence reference is admitted, retained, surfaced in query replies and used for occurrence-level evidence lookup. Implement it by reusing the existing application selected-input/member and maintained receipt helpers where their meanings fit; do not manufacture a SpicyRegs publication index from a bare Parquet file or re-label DocSpec receipts as the installed ETL policy. The actual choice of required Comments fields, evidence access, freshness/availability window and authorization is still a product input. This audit recommends SpicyRegs MCP as the first named application candidate; it does not claim the user has already frozen that selection.

Keep remote first independent Build/recovery/source read qualification separate. Remote corrections, evidence updates, flat export/upload, public hosting and full application update-to-readback remain outside that current qualified scope (`docspec-rs/README.md:15–24` and remote scope section; `src/engine/read.rs:18–20,43–44`). Browser/search/nested flat exports, combined flat groups and generalized SQL are not added by this patch. Measure local export plus actual MCP cold admission/read/retry when implemented; make no provider, complete-path latency, bounded whole-process memory or universal type claims from static tracing.
