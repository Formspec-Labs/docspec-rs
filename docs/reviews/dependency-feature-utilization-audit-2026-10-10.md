## What is new, known, or already delivered

- **New audit clarification:** OpenDAL is absent from Cargo.lock and is not the storage layer behind pinned Iceberg. `object_store` is present through DataFusion/Parquet. Native Iceberg uses the injected `StorageFactory`; [local construction](../../src/storage.rs#L75) supplies `LocalFsStorageFactory`. This confirms the existing storage-boundary conclusion and prevents an inapplicable OpenDAL tuning recommendation. It is not a new performance defect. See pinned [Iceberg I/O](https://raw.githubusercontent.com/apache/iceberg-rust/v0.10.1/crates/iceberg/src/io/mod.rs), [object_store APIs](https://docs.rs/object_store/0.13.2/object_store/index.html), and [OpenDAL's separate API](https://opendal.apache.org/docs/rust/opendal/).
- **Known and still present:** scalar preparation calls `read_file`; cardinality proof semi-joins before testing duplicates; native row-group rows equal compute batch rows; `open_pin` hashes metadata before `StaticTable` reads it; scan metrics are discarded with `.stream()`; DataFusion spill compression remains its default. Current source anchors and bounded next steps appear below.
- **Already delivered; do not propose again:** native column selection, selected-key discovery, native row statistics, BLAKE3's reader, streamed JSON fingerprints, shared join captures, admitted original metadata handles, maintained sequential stream composition, shared compacted-source interpretation, comparison normalization, and compaction-recovery retirement. The existing reports and [status](../STATUS.md) retain author verification. This refresh neither reran those checks nor remeasured their effects.
- **No new package or feature recommendation:** the inspected custom code implements identity, resource lifetime, field interpretation, or lifecycle rules around maintained primitives. The alternatives still need those rules and do not currently remove more code with equivalent guarantees.

## Transitive integration and custom-adapter checks

The [transitive matrix](../dependency-efficiency-audit-2026-10-10.md#re-exported-apis-and-material-transitive-packages) and [build/defaults analysis](../dependency-efficiency-audit-2026-10-10.md#enabled-defaults-duplicate-packages-and-build-footprint) remain applicable. Fresh lock/source inspection confirms these dispositions:

- **Arrow components, 58.4.0:** array/schema/buffer/data/select/cast plus arith/ord/row/string supply maintained buffers and columnar kernels; IPC supplies encoding and spill codecs; CSV/JSON arrive through defaults. No custom counterpart needs replacement. Root-only Arrow feature removal cannot eliminate features enabled by DataFusion. Keep type compatibility and measure the retained allocation behind views/slices.
- **DataFusion components, 53.1.0:** catalog/listing, common/runtime, datasource (Arrow/CSV/JSON/Parquet), execution/session, expression/adapter, logical/physical optimizer, plans/pruning, SQL and scalar/nested/table/aggregate/window function families provide execution. The source provider already uses `DataSourceExec`; [sequence](../../src/query/sequence.rs#L51) uses native `StreamingTable`. [Current provider guidance](https://datafusion.apache.org/library-user-guide/custom-table-providers.html) supports thin adapters; newer API examples are not pinned API proof. Keep `sqlparser` 0.61.0 / `recursive` 0.1.1 protection and the existing optimizer correctness guards.
- **Compatible alternative `iceberg-datafusion` 0.10.1:** the installed and [published scan](https://raw.githubusercontent.com/apache/iceberg-rust/04ae06bdb15a6fd7c7927d29d4e0f6a33de0f1f9/crates/integrations/datafusion/src/physical_plan/scan.rs) support snapshot selection. The decisive gaps remain admitted captured-reader injection, selected row-count statistics and stored-origin/position output. It still has one source partition. Replacing [NativeTable](../../src/query.rs#L148) would retain or lose these required adapters, not clearly simplify them. It is an evaluated alternative, not a current direct dependency.
- **Predicate pruning:** [NativeTable](../../src/query.rs#L161) selects columns but leaves filters to DataFusion. [Occurrence task checks](../../src/storage/occurrences.rs#L406) require complete, unfiltered files to preserve positions/counts. Iceberg has native filtering/range controls, but blanket pushdown here would violate that interpretation. A future values-only or proven origin-preserving path needs actual workload benefit and semantic qualification first. One active file still permits multiple native range reads; pinned [reader options](https://raw.githubusercontent.com/apache/iceberg-rust/v0.10.1/crates/iceberg/src/arrow/reader/mod.rs) separate file concurrency, range concurrency/coalescing and footer prefetch.
- **Bytes/HTTP/runtime:** `bytes` 1.12.1, `http` 1.5.0, `http-body` 1.1.0, `http-body-util` 0.1.5, `hyper` 1.12.0 / `hyper-util` 0.1.21, Futures components 0.3.34 and `tokio-util` 0.7.19 remain maintained transport/stream glue. [IPC](../../src/http/ipc.rs#L73) already uses [owner-backed Bytes](https://docs.rs/bytes/1.12.1/bytes/struct.Bytes.html#method.from_owner) to transfer its encoded Vec with its permit until the final clone drops. Its bounded sink adds admission, not a new encoder. Dictionary state and IPC compression need explicit qualification rather than enabling every feature.
- **Storage/cache/database:** `object_store` 0.13.2 does not configure Iceberg's injected I/O. OpenDAL is absent. `moka` 0.12.16 supplies native metadata caching; increasing its weight allowance is not a complete heap bound. `sqlx-core`/`sqlx-sqlite` 0.8.6 and `libsqlite3-sys` 0.30.1 support the native catalog/restore. [SQLite documents](https://www.sqlite.org/lang_vacuum.html#vacuum_with_an_into_clause) the current consistent compact copy and an incremental backup alternative; no observed bottleneck justifies another driver. Native expiration still cannot replace DocSpec cross-table protection and deletion reconciliation.
- **Codecs, allocator and build plumbing:** `async-compression` 0.4.50, `reqwest` 0.12.28, native codecs, `libmimalloc-sys` 0.1.49, `cc`/`pkg-config`/`vcpkg`, and proc-macro/quote/syn infrastructure have no project-owned substitutes to remove. Zstandard wrappers 0.13.3/0.14.0 share `zstd-sys` 2.1.0+zstd.1.5.7. Lockfile duplicates or optional SQLx backends do not establish duplicate runtime work or host linkage. Reuse the retained host graph; [additive Cargo features](https://doc.rust-lang.org/cargo/reference/features.html#feature-unification) require checking every parent before predicting a build saving.

The remaining implementations should be accepted one at a time using exact-result checks and measurements targeted to the work they intend to remove. This report adds current coverage and source confirmation; it does not establish a new speedup, whole-process memory bound, disk saving, or hosted qualification.
