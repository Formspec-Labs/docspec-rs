## Data flow and invariants

1. **Caller cancellation does not imply effect cancellation.** The public future owns only the join wait after spawning. Tokio drops that handle without aborting the task; the task still owns engine, guard and request permits (`src/engine/worker.rs:134`). The existing `Budget::blocking` closure keeps its own permits while started work runs (`src/budget.rs:114`). Losing a response does not create a new operation or revoke the original authority.
2. **Shared admission precedes dataset locks.** Public services acquire the maintenance reader first, then invoke their existing implementations. All inspected nested release/capture calls bypass public admission. A queued exclusive writer therefore cannot create the outer-reader/inner-reader cycle.
3. **Shutdown closes the race around admission.** `closing` is set before requesting the writer. A service waiting for a reader rechecks `closing` before spawning, while an already admitted reader remains covered by the drain (`src/engine/worker.rs:102`, `:132`, `:159`). Shutdown does not release workspace ownership while other Engine clones exist.
4. **Uncertainty never clears in-process.** `Custody::drop` poisons the host before `Admitted` releases its reader, and only the first abnormal drop leaks the host reference (`src/engine/worker.rs:59`, `:69`). Normal completion cannot clear that flag. This intentionally trades one retained descriptor for refusal to reopen while old actors may remain alive. A future destructive exclusive path must check the same host state before effects.
5. **Catalog acknowledgments remain part of custody.** SQLx SQLite owns commands on its connection thread and can commit despite lost acknowledgment (`sqlx-sqlite-0.8.6/src/connection/worker.rs:144`, `:254`, `:355`). Holding only a borrowed outer guard would not suffice. The patched task awaits the full catalog service and reconciliation.
6. **The local storage qualification is specific.** Pinned Iceberg's local filesystem adapter writes/deletes synchronously and closes with `sync_all` (`iceberg-0.10.1/src/io/storage/local_fs.rs:135`, `:179`, `:282`). The two `write_batches` branches joined in `src/engine/write.rs:505` therefore do not leave a detached local payload writer when one branch errors. This does not prove behavior of injected/remote adapters or drain all dependency-library read threads.
