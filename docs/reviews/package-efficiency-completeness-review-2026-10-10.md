# Package efficiency: independent completeness review

**Keep the current package family. The inventory is complete, and the useful remaining changes are at our call sites.** Finish narrow scalar reads and avoid the common redundant cardinality probe, then qualify native row-group sizing. One additional candidate deserves a bounded experiment when a representative query actually spills: DataFusion's existing spill compression can reduce temporary disk use without another storage implementation.

This is a static review of `8566235f32abc90ea21cfbd4b75f610766cfdc2d` and the inspected working tree on October 10, 2026. Concurrent cutover-admission changes are outside this review's correctness verdict. I parsed current Rust manifests/lockfile and Python imports, read production call sites and relevant fixture assertions, checked installed pinned upstream source, and consulted current official documentation. I ran one focused offline Cargo feature-tree investigation, but no builds, tests, benchmarks, corpus reads, or dependency changes. There is **no new measured speedup or disk-saving result** here.

## Where custom adaptation remains necessary

The important transitive boundary includes Arrow buffers/kernels/IPC, DataFusion expression/plan/execution crates, sqlparser/recursive protection, Futures/Tokio utilities, Bytes/HTTP/Hyper, `object_store`, Moka, SQLx/SQLite, compression wrappers and allocator bindings. Their pinned versions and existing decisions remain in the [transitive matrix](../dependency-efficiency-audit-2026-10-10.md#re-exported-apis-and-material-transitive-packages). This review covers those integration seams, **not every transitive implementation in Cargo.lock**.

- The compatible `iceberg-datafusion` 0.10.1 integration supports static snapshot selection, but its [scan](https://raw.githubusercontent.com/apache/iceberg-rust/04ae06bdb15a6fd7c7927d29d4e0f6a33de0f1f9/crates/integrations/datafusion/src/physical_plan/scan.rs) still lacks our admitted reader injection, selected row-count statistics and stored-origin output. It also has one source partition. Replacing [`NativeTable`](../../src/query.rs#L148) wholesale would lose required behavior. The narrower maintained [`StreamingTable`](../../src/query/sequence.rs#L51) is already used for shaped sequential streams.
- Native source scans currently apply early column selection but leave filters to DataFusion. The occurrence reader requires complete-file interpretation and stable positions; pushing a predicate into it blindly breaks that reasoning. [Current provider guidance](https://datafusion.apache.org/library-user-guide/custom-table-providers.html) recommends pushdown where the source can avoid I/O. Qualify a concrete values-only or origin-preserving pruning path before adding translation code or indexes.
- DataFusion's `object_store` registry does not configure Iceberg's separately injected storage. For the eventual remote adapter, use maintained [streamed/range reads, bounded stores and multipart APIs](https://docs.rs/object_store/0.13.2/object_store/index.html) where that adapter uses `object_store`, and Iceberg's storage interface for native I/O. Hosted credentials, retry and publication guarantees still need provider qualification.
- [`Budget`](../../src/budget.rs#L85) shares DataFusion's spill pool and adds application admission. Upstream pools do not account for every allocation; the pinned [Tokio blocking semantics](https://docs.rs/tokio/1.53.2/tokio/task/fn.spawn_blocking.html) also require permits to remain with work after caller cancellation. Keep those thin lifetime adapters. More DataFusion partitions do not split the [single native source partition](../../src/query.rs#L276).
- Iceberg's metadata cache weight does not include all heap-owned manifest entries. Favor existing admitted handle reuse over increasing its nominal capacity. The [retained upstream analysis](../dependency-efficiency-audit-2026-10-10.md#reuse-handles-and-captured-inventories-do-not-add-a-general-cache) remains applicable.
- **Compaction recovery retirement is delivered at `8566235`, not still in progress.** See the [retained gate](compaction-retirement-full-check-2026-10-10.log). Iceberg snapshot expiration does not replace DocSpec's cross-table protection or physical-deletion reconciliation. Reclaiming old layouts is a lifecycle result; this audit did not remeasure freed space. Native writers still do not return DocSpec content hashes, so their initial digest pass remains a justified exception until interception is simpler or measured worthwhile.
