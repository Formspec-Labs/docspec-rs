## Findings

**No open actionable findings.** Reviewed the uncommitted checkpoint after `e7f64a2`, including the corrections below. Static review only; the reviewer did not run tests or edit implementation.

**SR1 — CLOSED, performance: retain the captured lifecycle rows throughout traversal.** The initial walk repeatedly consulted the single cache entry shared across datasets. Another dataset could evict it between links and force repeated full lifecycle replay. `follows` now retains one existing `Arc<SnapshotRows>` (`src/engine/history.rs:44`) and reads both records directly from it (`src/engine/history.rs:248`). The immutable rows own their existing permit (`src/catalog.rs:32`); no second index or multi-entry cache was introduced. The native regression at `src/catalog.rs:442` replaces the cache with another dataset, makes the original native directory unavailable, proves repeated retained reads still work, and checks exact permit custody and final-drop release. Static trace and owner-executed targeted evidence close the finding.

**SR2 — CLOSED, performance: the warm traversal needs a cooperative yield.** The initial warm lookups could all complete immediately, leaving a long loop without suspension. Each continued link now calls maintained `tokio::task::consume_budget` (`src/engine/history.rs:123`). The pinned Tokio 1.53.2 implementation consumes cooperative budget and returns pending when exhausted; see its locally inspected `src/task/coop/consume_budget.rs:25` and `src/task/coop/mod.rs:343`, with the dependency pinned at `Cargo.lock:4505`. The retained snapshot survives these yields. This closes the missing-yield mechanism without a worker pool; it does not claim a measured latency bound for individual JSON parsing or a separately executed scheduler-fairness test.

**SR3 — CLOSED, test coverage: exercise decreasing predecessor revisions directly.** The corruption table now rewrites both records of an older predecessor after its child (`tests/succession.rs:363`). Pair equality still passes; the decreasing-revision check at `src/engine/history.rs:73` rejects the rewritten predecessor. This directly covers the branch that the earlier pair-mismatch and self-cycle cases did not reach.

## Patch summary

The checkpoint records each newly accepted release's actual predecessor in the same native lifecycle commit as the result and authority. It adds a metadata-only proof that both exact endpoints occur in forward order on one observed selected chain. It reuses the existing lifecycle table, bounded cache, native commit guard, dataset lock and CLI/HTTP application service. It does not add a SQL ledger, durable index, per-row event stream or payload verification path.

The distinct record is justified: an unbased source rebuild has no composition parent, while independent field-group selection can advance the accepted version without advancing its source boundary. Neither composition parents nor optional change tables encode complete accepted order.

Follow-up scope includes a retained `Authority.selection_revision` and shared head checks, plus an explicit small resource profile in the process-kill test harness. The revision ties the head to its accepted native commit across later admissions and invalidations. The test profile removes an accidental dependence on the production scratch reservation without changing production behavior or weakening the actual kill/resume assertions.

## Data flow and invariants

- **One observed state:** `prove_succession` opens a captured `View` once. Its retained rows supply the head and every link/result lookup. The reported revision describes that observed lifecycle snapshot, not a later head. Another dataset's cache replacement cannot change this state or force its replay.
- **Only acceptance creates succession:** source/backfill calls reach `select` after independent readback and their existing promotion guards. `select` records authority, result and link through one `Lifecycle::commit`. The existing native guard rejects stale metadata instead of refreshing stale application decisions (`src/catalog.rs:363`).
- **The head retains its accepted commit:** `selection_revision` is set to checked `view.revision + 1` inside selection (`src/engine/history.rs:170`). Later source admission (`src/engine.rs:543`) and invalidation (`src/engine.rs:440`) serialize the loaded authority, preserving the field. `read_head` requires the saved revision to be positive and no later than the authority row's own revision; `check_selected_link` requires exact equality with the selected pair. These checks add constant metadata and use the already retained rows, not additional scans.
- **Retry identity is preserved:** both selection callers return an existing operation result before calling `select`. A lost selection response therefore adds no second link; the new key cannot overwrite an accepted edge.
- **The actual previous selection supplies the edge:** `authority.release`, not the request base, creates `predecessor`. This captures merged independent backfills and ordinary unbased source replacement.
- **Order uses retained edges:** exact version references must occur on the observed head's chain. Equal endpoints still require membership. Decreasing stored commit revisions prevent cycles without a growing visited set. Boundary and eligibility comparisons reject inconsistent descriptions but do not infer ancestry.
- **Finite work:** the walk charges serialized link and result bytes, limits link count, and holds a metadata permit. Only one current link and a few identities/counters remain live; no vector of releases is accumulated. Its existing retained-row reservation stays alive across cooperative yields. The lifecycle cache already refuses excessive replay history before a commit can acknowledge unreadable state (`src/catalog.rs:263`). These controls do not establish a whole-process resident-memory ceiling.
- **No payload custody is promised:** proof uses recorded identity, not input data, native result files, optional changes or manifest file contents. It neither verifies present payload availability nor authorizes cleanup. All destructive maintenance remains outside this checkpoint.
- **No detached workers:** traversal creates no spawned task; cancellation drops its local reservation and dataset-lock guard. Native cold replay retains the existing reader behavior, whose wider upstream allocation limits remain unqualified.
- **A fixture resource profile remains a fixture:** `kill_after` writes limits beneath its disposable test root before starting the child; `resume` reads that same file. Every current `resume` caller follows `kill_after` in its fixture. The CLI parses the profile through its existing bounded JSON reader (`src/main.rs:124`). The test-only correction changes neither `Limits::default` nor production disk checks. It qualifies recovery under the explicit profile, not the production resource target.
